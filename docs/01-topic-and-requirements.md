# 选题范围与需求分析

## 1 题目及适用情况

建议题目：**基于大语言模型的智能出题与错题管理系统设计与实现**。

如果导师要求体现知识依据，可以讨论改为“面向学习资料的可追溯智能出题与错题管理系统设计与实现”。题目中的“可追溯”指能够查看题目使用的资料及引文，不表示自动证明题目正确。

本项目适合能够完成 Python 基础、数据库和 Web 开发学习，且希望以 API 应用为主线的本科生。项目重点是把资料处理、模型输出约束、题目管理、练习判分和错题复习整合为可靠的软件流程。它不训练基础模型，不需要 GPU；也不把调用 API 本身写成算法创新。

开始前向导师确认：是否接受 API 应用型课题；是否要求算法改进或基线对比；是否必须真实部署；论文篇幅、外文阅读、代码量和测试材料有无明确要求。没有统一标准可以保证一个题目一定通过毕业审核。

## 2 问题描述

学习者已经有一份允许使用的学习资料，希望快速形成小规模练习题。普通题库不一定覆盖这份资料，而直接使用模型生成题目可能出现错误答案、虚构依据、格式混乱和重复题目。作答后如果只得到分数，后续还需要人工记录错题。

本系统完成一条可检查的闭环：导入资料，产生带出处的单选题，完成练习，查看答案解析，将答错题目收录至错题本，再进行复习。该闭环的价值需要通过功能测试和人工质量评价来验证，不预先宣称提升学习成绩。

## 3 使用者和场景

- 使用者：一名在自己电脑上复习的学习者。
- 资料来源：原创笔记、公开授权资料，或获得许可且允许输入模型服务的资料。
- 主要场景：对一个章节生成少量单选题；检查资料依据；完成练习；定期复习尚未掌握的题。
- 数据规模：课程章节和小型题库级别。不要未经测试写成可服务全校的生产系统。
- 部署范围：本机浏览器访问本机后端，默认监听 127.0.0.1。系统没有完整账户、角色和多租户隔离。

## 4 最小完成范围

| 编号 | 需求 | 可观察的验收条件 |
| --- | --- | --- |
| R01 | 导入资料 | 可粘贴文本或导入 TXT、Markdown、可提取文字的 PDF；空白及非法文件得到明确错误 |
| R02 | 生成题目 | 选择资料后产生单选题，题目含选项、答案、解析和原文依据 |
| R03 | 演示模式 | 不设置 API 密钥也能走通业务流程，界面明确区分模式 |
| R04 | 真实模型接入 | 在显式确认资料外发后由后端调用；密钥不出现在浏览器和公开仓库 |
| R05 | 练习与判分 | 选择题目开始练习；提交后展示得分与题目反馈；不能靠客户端随意提交分数 |
| R06 | 错题管理 | 答错记录进入错题本，可查看依据、记录复习或掌握状态 |
| R07 | 历史与统计 | 查看练习记录、作答反馈及汇总；统计口径明确 |
| R08 | 数据导出导入 | 导出本地备份，按程序支持的格式校验导入，不把文件存在当作恢复成功 |
| R09 | 可复现运行 | 依赖、启动命令、默认数据和测试过程有文档 |
| R10 | 生成质量评价 | 真实 API 题目单独采样、人工评分；演示题不能混入真实模型结果 |

R10 是毕业设计实验要求，不代表系统已经做完真实模型实验。若没有预算或模型访问条件，应与导师说明并调整验证范围。

## 5 本版明确不包含的功能

- 扫描件 OCR、手写识别、Word 文档和图片解析。
- 多人注册登录、老师布置班级任务、在线考试防作弊。
- 大规模向量数据库、模型微调、从零训练、知识图谱。
- 对填空题或主观题进行可靠自动评分。
- 科学证明学习成绩提升，或提供医学、法律等高风险考试认证。
- 生产级公网部署、付费服务、自动扣款或任意第三方网站集成。

这些内容可以放在“未来工作”。未经实现和测试，不要在需求完成表或论文结果中勾选。

## 6 非功能需求

**可理解性。** 错误提示区分格式错误、资料不足、模型调用失败与存储失败。用户应该知道能否重试、是否可能再次计费。

**可靠性。** 无效模型结果不能直接进入题库；一次提交不能产生互相矛盾的分数、历史和错题数据；异常路径应有测试。

**可追溯性。** 保存题目所属资料和引用文本。引用存在于原文是最低验证条件，引用是否支持答案仍要人工审核。

**安全与隐私。** 本地保存并不等于加密保存；真实模型模式会发送用于生成的资料文本。只导入有权使用的内容，不将个人身份、成绩、真实试卷或受限教学资料放入公开仓库。

**可维护性。** 配置、数据访问、生成服务、接口和页面尽量分离；用测试锁定行为；记录依赖版本。

**性能。** 先记录本机启动、资料导入和模型生成的实际耗时，再定义指标。模型响应时间受网络、服务排队和输出长度影响，不把一次快的结果当作稳定 SLA。

## 7 硬件与预算假设

本地部分承担 Web 服务、SQLite 和轻量文本处理，没有本地大模型推理。本指南以普通 Windows 或 Linux 电脑为目标，建议有 8 GB 内存及数 GB 可用磁盘作为开发环境起点。这是实践建议，不是已经测出的最低配置；请记录自己机器的 CPU、内存、操作系统和 Python 版本。

- 演示模式：项目不发起模型 API 请求，因此不产生模型调用费用。上网下载依赖等仍使用自己的网络。
- 真实模式：需要自己可使用的服务商账户、适用模型权限和预算。API 是否收费、怎样计费、区域可用性以服务商当时官方说明为准。
- 不需要先租服务器、不需要买 GPU、不需要购买向量数据库。
- 费用记录可用“输入 token 数 × 输入单价 + 输出 token 数 × 输出单价”，注意把每千或每百万 token 的计价单位统一。缓存、请求费、最低收费及其他项目以实际账单为准。
- 先人工确认小额预算，测试一次 1–3 题，再决定是否扩大实验；不要无上限地重试失败调用。

## 8 可写进开题报告的研究目标

以下是目标写法，需要由学生按实际计划改写：

1. 设计资料、题目、练习和错题之间的数据结构，形成可重复运行的学习流程。
2. 设计带资料边界与输出字段约束的模型调用方法，研究结构校验及来源检查对错误输出的筛除作用。
3. 实现本地 Web 原型并覆盖主要成功、边界和失败场景。
4. 建立人工评价标准，评估生成题目的答案正确性、来源支持、唯一性与可用性，并分析失败案例。

这里第 2、4 项可以形成分析内容。结果可能显示仍存在不足，真实分析失败原因同样是有效成果。
