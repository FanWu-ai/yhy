# 答辩演示与常见问题

目标是让评委看到一个可以解释、可复现、边界清楚的系统。不要背诵超出自己理解的术语；不确定的地方直接说明目前限制和可验证的下一步。

## 1 答辩前一天

- 固定展示代码版本，保存提交 ID 和依赖列表。
- 在自己的电脑上重跑测试和完整演示，不把开发电脑成功当作演示电脑成功。
- 使用不含隐私的原创样例资料，准备独立演示数据库，避免展示个人记录。
- 备份原数据库，测试恢复方法，切勿临时删库赌运气。
- 准备无需联网的演示模式；如展示真实生成，提前核实模型权限、网络和小额预算。
- 准备真实实验记录、失败案例和测试结果，模型效果图表必须能回溯原始数据。
- 录制一段本版系统的真实操作视频作为故障备份，并标明录制日期与模式。视频不能替代现场不具备的功能。
- 确认教室显示比例、字体大小、电源、浏览器和本机端口。

## 2 建议的十分钟结构

根据学校时长调整，不需强行套用。

| 时间 | 内容 | 展示重点 |
| --- | --- | --- |
| 0:00–1:00 | 问题与范围 | 面向学习资料的出题及复习闭环，单用户本地原型 |
| 1:00–2:00 | 架构与数据 | 浏览器、后端、SQLite、可选模型服务，外发边界 |
| 2:00–5:30 | 实际操作 | 资料 → 题目 → 作答 → 错题 → 复习 → 历史 |
| 5:30–7:30 | 测试与评价 | 自动测试和真实模型评价分开，展示实际结果 |
| 7:30–9:00 | 个人工作与取舍 | 自己理解、修改、验证了什么，为什么这样设计 |
| 9:00–10:00 | 限制与总结 | 无多用户、无 OCR、语义错误仍需人审，后续工作 |

## 3 演示操作脚本

1. 打开主页，先说清“现在是演示模式”或“现在使用哪家服务的哪个模型”。
2. 导入一份小型原创资料，显示提取后的文本，指出系统依据来自哪里。
3. 生成或加载演示题，查看一题的解析和引用，说明可追溯不等于保证正确。
4. 开始一组少量题目的练习，有意答错一题，其他题正常作答。
5. 提交，核对得分和逐题反馈。
6. 打开错题本，找到刚才答错的题，完成支持的复习或掌握操作。
7. 打开历史与统计，指出统计分母和刚才记录的变化。
8. 展示导出备份，说明备份包含什么；现场无必要不要向正式数据库导入不确定文件。
9. 打开一份实际测试或实验结果，说明自动测试只证明程序行为，人工评分如何评价题目。

演示模式没有真实模型调用，因此不要将演示速度、正确率和示例题内容说成 API 实时生成性能。若展示真实模式，外发前明确使用的是允许发往该服务的公开资料。

## 4 二十个常见问题

### 1 为什么选择这个题目？

回答应联系具体问题：学习资料需要转成练习，生成内容需要依据，做错后需要复习记录。展示你怎样把这三件事接起来，而不是只说“大模型很热门”。

### 2 你的工作是不是只调用了一个 API？

模型能力来自服务商，应明确承认。需要展示自己理解或实现的资料处理、输入输出约束、校验、数据库、判分、错题闭环、异常处理和评价。具体贡献按真实工作记录说，不把框架和模型能力据为己有。

### 3 为什么不用自己训练模型？

本课题定位为应用系统设计，使用 API 可以把时间集中在业务和可靠性。如果专业要求模型训练，应在开题时调整范围；不能把调用 API 描述成训练完成。

### 4 演示模式有什么意义？

用于不联网、无密钥条件下复现页面和数据流程，以及降低自动化测试的不确定性。它不是大模型质量的证据。

### 5 引用原文就能消除幻觉吗？

不能。程序可以检查引用是否出现于材料，但引用可能无关、断章取义，答案也可能错误。需要结合语义人工评价，并保留失败案例。

### 6 本项目是 RAG 吗？

先按代码回答。如果只是把选定资料放入上下文并校验引文，就说资料约束生成。只有实现明确的分块、检索和返回上下文流程后，才描述相应检索增强机制，不宣称存在向量数据库或检索算法。

### 7 怎样防止模型输出格式错误？

解释提示词要求、JSON 解析、字段与取值检查，以及存库前的规则验证。指出提供方结构化输出支持不一致，提示词要求并不是绝对保证。举一个测试中的非法响应。

### 8 正确答案在前端还是后端判断？

本项目应由后端依据已存题目判断。指出实际提交接口和判分代码，说明客户端提交的是选择，不是可信分数。本机单人原型并不具备正式在线考试防作弊能力。

### 9 连续点击提交会怎样？

展示实际实现与测试，说明重复提交被拒绝或按已实现规则处理。不要泛称有分布式幂等机制，除非实际设计了那套机制。

### 10 为什么用 SQLite？

适合本地单人原型，安装负担小，数据可持久化。它不是为本系统已验证的大规模并发方案。扩展到多人服务还需要权限、数据库迁移和并发测试。

### 11 为什么不做登录？

当前范围是本机单用户；加入登录会引入账户、密码存储、会话和数据隔离工作。当前没有这层保障，所以默认只监听本机，不宣传为可直接上线的多人平台。

### 12 PDF 为什么有时不能识别？

本版提取 PDF 已有文字，不执行 OCR。扫描件可能只有图像；复杂布局还可能导致顺序和符号问题。可以换可复制文字资料或人工整理文本，不能把空解析结果当作成功。

### 13 模型 API 失败怎么办？

说明界面错误、服务端记录、保留已有数据和人工重试方式。真实请求重试可能再次计费，不能无限重试。演示模式可用于继续说明业务，但必须告知切换。

### 14 密钥安全吗？

说明密钥经环境配置读取且不应返回前端、不提交仓库。不要说绝对安全；本地终端历史、日志、恶意软件和错误分享仍有风险。展示不含密钥的配置示例。

### 15 学习资料会发到哪里？

演示模式不调用模型服务。真实模式把需要的资料文本发给配置的服务商，所以需要用户明确确认并自行核对服务商数据规则。原始本地数据库仍要妥善保管。

### 16 怎样证明题目质量？

介绍自己的资料集、模型与参数、请求数量、评分量表、原始计数和失败。若未完成真实实验，就说尚未完成，不能拿自动测试或演示题补位。

### 17 有效题少于请求题数怎么办？

可能因为模型响应不足或校验过滤。报告目标题数、实际产出和可用题数量，解释减少的原因。只展示保留好题会产生选择偏差。

### 18 错题本能证明学习效果提升吗？

不能单凭功能存在证明。当前可说明记录和复习过程支持；学习效果需要合适参与者、对照和评估设计，超出本版就如实说明。

### 19 开源与 AI 辅助用了哪些？

按真实记录回答依赖、来源与 AI 辅助范围，展示自己的理解、修改、测试和实验。遵守学校政策，不把第三方或 AI 产出说成全部手写原创，也无需公开不相关私人对话。

### 20 下一步最值得改什么？

结合实际失败选一个：更好的来源语义校验、题目人工审核、长文上下文选择、复习策略等。说明需要改的数据、流程和验证方法，比列十个未做功能更有说服力。

## 5 现场故障处理

- 网络或服务商不可用：说明实际故障，切演示模式继续展示业务；真实效果用已经完成并有原始记录的实验解释。
- 端口被占用：停止重复进程或使用事先测试的备用端口。
- 资料导入失败：展示错误信息，换准备好的合法文本，并解释格式限制。
- 数据混乱：停止继续写入，使用事先备份的独立演示数据库；不要现场删除唯一实验数据。
- 不会回答实现细节：指出相关代码，说明当前理解和需要核查的部分；不要临时编造架构。

## 6 演练验收

请一个不了解系统的人按你的说明尝试启动，并提出五个问题：数据保存在哪、有没有发给外部模型、为什么某题正确、怎样查看一次错题、怎样知道测试确实执行过。若你能用界面、代码和证据一致地回答，通常比背几十页 PPT 更有用。
