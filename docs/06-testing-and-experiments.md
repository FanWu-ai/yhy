# 测试方案与真实实验记录

本章把“软件能不能按约定运行”和“模型题目是否有教学价值”分开验证。下面的样本数量和流程是可执行的实验建议，**不是已经完成的实验结果**。所有最终数值必须来自学生实际运行与人工审阅。

## 1 四层证据

| 层次 | 方法 | 能说明什么 | 不能说明什么 |
| --- | --- | --- | --- |
| 静态检查 | Ruff、JavaScript 语法检查 | 已配置规则下的代码及语法问题 | 业务正确、模型准确 |
| 自动化测试 | pytest、模拟 API 响应 | 确定输入下的程序行为、错误处理和数据一致性 | 真实服务稳定性与题目正确率 |
| 手工业务验收 | 浏览器完成指定任务 | 页面和后端组合流程可用 | 全部边界情况都正确 |
| 真实模型实验 | 合法资料、实际 API、盲化人工评分 | 特定模型、资料和条件下的样本质量 | 所有学科、所有用户都同样有效 |

演示模式属于前面三层的辅助，不属于真实模型效果证据。测试中模拟出的完美响应也不能计入模型评分。

## 2 自动检查怎样记录

使用 [安装说明](02-install-and-run.md) 中全部检查命令。记录：日期、提交 ID、系统、Python 与 Node 版本、依赖安装情况、命令、退出码、测试数、跳过项目和错误摘要。

Linux 示例：

```bash
git rev-parse HEAD
.venv/bin/python --version
node --version
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
node --check app/static/app.js
```

保存终端输出或导出日志，不手写一张全是“通过”的表。`skipped`、`xfail`、收集失败、依赖安装失败应分别记录。仓库 CI 和本机检查也是不同执行环境，需要分别核实。

官方 pytest 文档说明测试发现与断言方法；Ruff 文档说明检查和格式化工具的定位。[pytest](https://docs.pytest.org/en/stable/getting-started.html)、[Ruff](https://docs.astral.sh/ruff/)

## 3 功能与边界测试清单

以下是验收设计清单。是否已有自动测试覆盖，必须检查当前 `tests/` 和执行结果后填写；不能直接把这一表当作已执行的测试报告。

| 编号 | 操作或输入 | 预期观察 |
| --- | --- | --- |
| F01 | 导入正常中文文本 | 资料可读取且与输入一致，字符与换行没有严重损失 |
| F02 | 导入只有空格的资料 | 返回可理解错误，不生成空记录 |
| F03 | 导入不支持类型或超限文件 | 拒绝且说明限制 |
| F04 | 导入可复制文字 PDF | 解析出正文；人工核对表格或特殊符号 |
| F05 | 导入扫描 PDF | 不误报成功；提示无可用文字或解析问题 |
| F06 | 演示生成 | 不要求密钥、不访问真实模型，输出标记清楚 |
| F07 | 未确认资料外发而请求真实生成 | 阻止外发，不把一次失败偷偷切换成真实请求 |
| F08 | 缺少密钥或模型配置 | 明确报错，不暴露秘密 |
| F09 | 模拟非法 JSON、字段缺失、答案不在选项内 | 输出不进入可用题库 |
| F10 | 模拟引文不在资料中 | 来源校验拒绝或按实现返回明确错误 |
| F11 | 练习中查看网络响应 | 开始练习接口不在不必要字段里提前给出答案 |
| F12 | 有意做错一题并提交 | 得分、解析和错题本一致 |
| F13 | 相同练习连续提交 | 不重复累计数据，不产生不一致历史 |
| F14 | 更新错题掌握状态 | 状态保存；刷新后仍一致 |
| F15 | 停止重启服务 | 资料、题目、练习和错题按保存规则保留 |
| F16 | 导出并在隔离数据库导入 | 内容按备份范围恢复，数量和关联正确 |
| F17 | 导入损坏或不支持版本备份 | 拒绝或明确报错，不破坏已有数据 |
| F18 | 快速重复点击、网络失败、刷新或返回 | 页面不卡在错误状态，不静默丢失已保存结果 |
| F19 | 输入含 HTML/脚本文本的资料 | 页面按文本显示，不执行资料中的脚本 |
| F20 | 统计空数据和多次练习 | 无除零错误，统计分母清楚且可手算复核 |

## 4 人工实验的研究问题

建议选择少量具体问题，不要泛泛写“验证系统先进性”。

- Q1：指定资料下生成的单选题，有多少在答案正确且有唯一答案的前提下可以直接使用？
- Q2：可见来源引文有多少真正支持答案？“引文在原文中”与“引文支持结论”的差距多大？
- Q3：哪些错误最常见，发生在资料抽取、模型理解、干扰项设计还是输出格式阶段？
- Q4：一次生成请求的耗时、失败率和实际花费是多少？

如果要研究“比不加约束更好”，还需要实现并记录公平的基线流程。仓库现有演示模式不是这种基线。

## 5 一个可承受的小规模方案

下面是一份可执行建议，真正的样本量由导师、预算和时间确定。

1. 自己编写或选择 12 段已授权资料，来自 3 个自己能核对的主题，每个主题 4 段。每段长度控制在相近区间，例如约 500–1,500 个汉字，并记录实际字符数。
2. 用 2–3 段额外资料调试提示词和流程。这些开发样本不进入最终测试集合。
3. 锁定代码版本、模型标识、提示词模板、生成题数与其他参数。
4. 每段资料请求 3 道题，重复 2 次作为随机性观察，共 24 次请求、目标 72 题。目标题数不等于实际有效题数。
5. 保留每次失败及不足题数，记录耗时、原始响应、校验结果和可见计费信息。
6. 将成功产生的题目随机编号，尽可能隐藏是哪一次请求、哪种比较条件，让评分者按统一量表审阅。
7. 至少由一名熟悉资料的评分者审核全部题；条件允许时让第二人独立复核一部分或全部样本。得到同意，使用匿名编号，不公开评分者身份。
8. 对分歧单独记录，在保留原始评分的情况下讨论得出最终意见。
9. 汇总指标、举出失败案例，说明样本小、主题少、模型会更新等限制。

这是一个低成本示例，不代表经过统计功效分析的样本量。若只评 10 道题，应明确报告 10 道，不能外推为稳定总体结论。

## 6 人工评分标准

每道题评分前必须同时看到资料、题干、四个选项、标准答案、解释和引用。建议先采用容易解释的 0/1/2 等级，细则如下。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 答案正确性 | 答案错误或无法判断 | 依赖模糊条件，需修改 | 在资料语境下明确正确 |
| 来源支持 | 引文无关或不支持结论 | 部分支持，仍需补充条件 | 资料依据足以支持结论 |
| 唯一答案 | 多个正确或无正确选项 | 存在有争议的选项 | 只有一个明确正确选项 |
| 干扰项质量 | 明显无关、重复或透露答案 | 部分干扰项较弱 | 合理、互斥且有辨别价值 |
| 表达清晰度 | 语病或歧义影响作答 | 小改后可读 | 题干选项完整清晰 |
| 解释一致性 | 与答案或原文矛盾 | 大体正确但不充分 | 与答案、原文一致且有说明 |

另设二元标签：是否存在资料之外的实质性主张、是否与其他题重复、是否可直接使用、是否涉及敏感或不适宜内容。

“可直接使用”的判定规则在评分前确定，例如：答案正确性、来源支持、唯一答案必须均为 2，其他维度均至少 1，且没有未经依据的实质主张。不要事后为了提高可用率放宽标准。

“未发现错误”只能针对已审阅样本；不能写成系统已彻底消除幻觉。来源引文存在于文本中，也可能被截取到失去语境，或与正确答案无关。

## 7 指标及分母

- 请求成功率 = 成功返回可保存题目的请求数 / 总请求数。
- 请求级失败率 = 失败请求数 / 总请求数。按网络、模型、格式、来源、其他错误再分类。
- 题目交付率 = 最终保存题数 / 请求目标题数。只报告成功请求会掩盖失败，必须保留总请求分母。
- 人工可用率 = 被人工判为可直接使用的题数 / 实际人工审阅题数。
- 答案正确率 = 答案正确性为 2 的题数 / 实际人工审阅题数。
- 来源充分支持率 = 来源支持为 2 的题数 / 实际人工审阅题数。
- 有效可用产出率 = 可直接使用题数 / 请求目标题数。该指标同时反映失败与质量，需同时报告其他指标以便解释。
- 每题平均成本 = 本次实验实际计费总额 / 成功产出题数；若只计算可用题成本，分母改为可用题数并明确标注。
- 延迟报告中位数及范围；样本足够时再报告第 95 百分位，并说明计算方法。失败超时单独保留，不能直接删掉。

当分母为 0 时填写“不适用”，不能填 0% 来伪装有结果。服务商未返回 token 或没有取得账单时填写“未知”，不要按字数伪造 token。估算成本必须和实际账单分开。

同时保留“39/48”这类原始计数，避免只有百分比。小样本比例建议补充区间估计，方法与工具要可复现；题目共享同一资料，存在相关性，不能把每题都当作完全独立的大样本。

## 8 如果要做对比或消融

可选比较：同一服务商同一模型、同一资料、相同题数，一组使用简单生成指令，另一组使用本项目的资料约束、结构约束与来源校验。

开展前必须补齐：基线实现或操作脚本、完整可公开提示词、统一参数、运行顺序、失败记录和评分盲化。若提示词模板改过，要保存版本而不是覆盖后重新解释旧结果。

注意区分两个指标：模型原始输出质量，与过滤后保留题目的质量。过滤掉坏题可以提高保留集合的质量，同时降低产量。不能只公布过滤后的百分比来声称模型本身得到提升。

如果没有实施基线，论文写“单系统评价”，不写“优于传统方法”或“提升 XX%”。本项目默认不提供已完成的消融实验结果。

## 9 试用与学习效果的边界

可以请取得同意的同学用公开样例完成几项任务，记录是否成功、操作耗时和主观困难。这叫可用性试用，不能据此证明学习效果提升。

真正的学习效果研究涉及参与者选择、对照、前后测、混杂因素和学校伦理要求。若无条件开展，就在论文限制中说明，没有必要虚构班级规模、调查问卷或显著性结果。
