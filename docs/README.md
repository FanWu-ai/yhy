# 毕业设计使用指南

本指南面向第一次独立完成软件类毕业设计的本科生，围绕“基于大语言模型的智能出题与错题管理系统设计与实现”，说明怎样运行代码、理解实现、补充实验、撰写论文和准备答辩。它是学习与开发材料，不是可以直接署名提交的毕业论文。

系统定位为单人、单机使用的教学原型。默认演示模式无需模型密钥和 GPU；真实模型模式通过服务端调用兼容的模型 API。毕业设计是否符合要求，以本校任务书、导师审核和学术规范为准。

## 先做哪几件事

1. 阅读 [选题与需求](01-topic-and-requirements.md)，将范围给导师确认，尤其确认应用型大模型项目是否满足专业要求。
2. 跟着 [安装与运行](02-install-and-run.md) 启动默认演示模式，不要先购买 API。
3. 完成 [操作与演示](03-use-and-demo.md) 中的一轮“资料 → 出题 → 作答 → 错题 → 复习 → 导出”。
4. 对照 [架构与接口](04-architecture-and-api.md) 读代码，能说明每条数据从哪里来、怎样保存。
5. 按 [开发计划](05-development-roadmap.md) 做自己能够解释的修改，留下版本记录。
6. 运行 [测试与实验](06-testing-and-experiments.md)，真实填写原始记录，再写 [论文](07-thesis-writing.md)。
7. 准备 [答辩](08-defense-guide.md)，最后核对 [交付清单与学术诚信](09-delivery-and-integrity.md)。

## 记录模板

`templates/` 中提供开题提纲、周报、需求追踪、人工评分、生成记录、测试记录和交付检查模板。空白意味着尚未执行。不要把占位符、预期结果或演示结果当作实验事实。

建议把个人论文、真实实验原始数据和学校表格保存在仓库之外的私有目录。公开仓库只保存你有权公开的代码、原创示例与去标识化材料。

## 三个容易混淆的结论

- 自动测试通过，说明这些测试覆盖的程序行为符合预期；不能证明大模型所有题目都正确。
- 演示模式能完整走通业务流程，但没有调用真实大模型，不能用于证明模型生成质量。
- 真正的毕业设计工作包括理解、改进、测试、记录、写作与答辩；下载代码运行成功只是起点。

本套文档按仓库实现编写。环境实际运行记录以根目录验证报告和你自己的复现实验为准；未执行的 Windows 实测、真实 API 实验和人工质量评分不能记为已通过。
